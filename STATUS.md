# HypernetSPApp — status & handoff

On-device iOS port of the bounded **SP-evict** soft-prompt reasoner (APP_SPEC.md / `tiered_rag_mlx.py`),
to `mlx-swift`. **Milestone 1 = a faithful inference core that reproduces the Python reference, validated
on real hardware.** UI and the tiered-memory/intent layer come next.

A Swift Package (`~/HypernetSPApp`) that natively re-implements the model pipeline:

| File | Role |
|---|---|
| `Sources/HypernetSP/Pooler.swift` | Port of `pooler_mlx.PoolerMLX` (AttnPoolSP): manual MHA (packed QKV in_proj, head-avg attn → eviction mass), LayerNorm, GELU FFN, sinusoidal PE, out-norm scaling. `forward` + `forwardWithMass`. |

## Key constraints discovered

1. **mlx-swift cannot run on the iOS Simulator.** MLX's C++ `Scheduler` eagerly creates a Metal GPU device at init, which **aborts (SIGABRT) on the simulator** — even with `Device.setDefault(.cpu)`. So:
   - **Validate on macOS** via `xcodebuild` (real Metal; same MLX stack a real iPhone uses).
   - `swift test` (SwiftPM CLI) fails differently — "Failed to load the default metallib" — because the CLI doesn't stage MLX's Metal bundle. Use `xcodebuild`, not `swift test`.
   - **Ship/run on a physical iPhone** (GPU works there).
2. **Build Release, not Debug.** Debug builds MLX's C++ kernels at `-O0` → CPU inference is ~10–50× slower (48 min for 160 tokens). Release → optimized → CPU greedy ≈ 0.7 tok/s for the 1.5B; a real iPhone GPU is far faster.
3. **CPU↔GPU parity:** the Python reference fixtures were regenerated with `mx.set_default_device(mx.cpu)` and the Swift test forces `.cpu`, so both sides use the CPU backend → exact token match.
4. In Release, `@testable import` fails (testability off); the test uses plain `import HypernetSP` (all needed symbols are `public`).

## Long-generation stabilization (2026-06-11)

Findings on device (iPhone 16e):
- **Memory is NOT the bottleneck.** With the increased-memory-limit entitlement the app reports
  **~5091 MB available** (`os_proc_available_memory()`) *after* the model is loaded — the 4-bit model
  (embed/lm_head included) + fp32 pooler leave huge headroom. fp16 pooler is unnecessary for memory.
- **The real constraint is the iOS app lifecycle: Metal rejects GPU work from the background.** A long
  (multi-minute) generation that runs while the app loses foreground aborts with
  `[METAL] … Insufficient Permission (to submit GPU work from background)` → SIGABRT. A short (~7 s, 256-tok)
  generation finishes inside the foreground window and is fine.
- Mitigations shipped:
  - `Options.shouldContinue` — checked at each chunk; the app passes a foreground flag (updated from
    `UIApplication.didBecomeActive/willResignActive`), so generation **stops cleanly and returns the partial
    result** instead of crashing when the app is backgrounded.
  - `UIApplication.isIdleTimerDisabled = true` (on launch + during compute) so the screen doesn't auto-lock
    while a long generation runs in the foreground.
  - A `beginBackgroundTask` assertion for a short grace period.
- **Operating rule:** long on-device generation must run with the app **foreground (screen on)**. With that,
  the 5 GB headroom makes long CoT stable. (The residual risk is a background transition *during* a single
  chunk's GPU submit — a ≤1–2 s window — which the per-chunk guard can't fully close; chunk C=64 keeps it small.)
- SP-evict cost note: each chunk re-prefills `[SP | raw window]`, so long generation with `rw=1024` re-encodes
  ~1024 tokens every 64 generated → wall-clock is dominated by re-prefill, not decode. Lowering `rw` or raising
  `C` trades fidelity granularity for speed if long-gen latency matters.

## Multi-turn bounded KV — "infinite rally" (2026-06-11)

`SPModel.continueStream(_:maxNew:options:)` + `ChatSession` carry a whole conversation as a growing
token list with **no permanent prompt prefill** — the entire history is evictable. Each chunk: tokens
beyond the raw window are pooled into 32 soft prompts (mass-evicted to `maxD`), the KV is rebuilt from
`[SP | raw window]`, and `chunk` tokens are decoded. So conversation length grows unbounded while the
live KV stays O(rw + maxD). This is the project's core value for RAG-heavy chat (context fills tokens fast).

**Demonstrated on iPhone 16e (GPU):** a RAG-heavy turn (~20k-token "retrieved" context injected) →
```
convo=19737 tok · KV kept=4096/4096 · evicts=8 · 12.3 tok/s · avail=1835MB
```
A **19,737-token conversation ran with the KV cache bounded to 4096** (8 evictions compressing the distant
history), the model still answered, and ~1.8 GB headroom remained. Plain single-turn replies run ~27 tok/s.

The app (`AppModel.autoDemo`) injects this RAG-heavy first turn on launch to make the bounded-KV behavior
visible, then `generate()` continues the same `ChatSession` for each user message (true multi-turn).

## L3 web search (2026-06-11)

`WebSearch.swift` — keyless, **JSON-only** (no HTML scraping, robust on iOS): DuckDuckGo Instant-Answer
API for a quick abstract + Wikipedia (`api.php` search → `rest_v1/page/summary` extract), returning
`"Title: extract"` snippets. Port of the Wikipedia backend in `runtime/web_search.py`. Wired into
`Assistant.turn`: a **`lookup`** (world-question) turn fetches web snippets and injects them; `recall`/
`command`/`math` use personal memory; `math` never web-searches. **Validated live on macOS** (WebSearchTests):
"emperor of Japan" → Naruhito (126th monarch); "Mount Fuji height" → 3,776.24 m. ~3 s for two queries.
HTTPS to wikipedia.org / duckduckgo.com works under default ATS (no Info.plist change).

**Device-run caveat (important):** iOS suspends the app (and rejects GPU work) when it's not foreground,
and the **developer disk image won't even mount on a locked phone**. Long multi-turn demos via `devicectl`
kept being killed because the phone auto-locked. To run on device: **unlock the phone, set Settings →
Display & Brightness → Auto-Lock = Never, open the app and keep it foreground.** Short turns (single reply,
~27 tok/s) complete fine; the memory/routing logic itself is fully validated on macOS.

## Fidelity refinements (2026-06-11)

`Refine.swift` + reworked `Assistant.turn`, ported from `tiered_rag_mlx`:
- **Groundedness guard** (`isGrounded`, port of `is_grounded`): a retrieval-grounded answer must echo a
  salient *novel* token (code/number/capitalised/≥5-char) from the context, not just the question.
- **Isolated clean-quote recall/lookup**: recall & lookup now generate from ONLY the retrieved context +
  question (`SPModel.generate`, fresh KV — no conversation SP that could bleed a distractor), with up to
  **3 re-rolls** if the answer isn't grounded. Recall with no hit → "I don't have that saved" (0 tokens).
- **Specificity span pinning** (`specificCandidates` = `_CAND` regex; `specificSpans` scores each span with
  the specificity head ≥0.6): pins the *specific spans* (`$120`, `QX7-2291`, `Naruhito`, `3pm`) of a turn,
  not the whole text.
- **Light anaphora** (`expandQuery`): a query opening with a bare pronoun and no proper noun gets the most
  recent pinned entity prepended before web search.
- command/math/chitchat still continue the **bounded** conversation; recall/lookup are isolated.

Validated on macOS (RefineTests): groundedness True/False cases, span enumeration + scoring, answer
extraction. On device: a lookup turn runs the **isolated** path at **35.4 tok/s** (faster + lighter than
the bounded path — no per-chunk re-prefill), grounded on the first sample.

## Decode policy aligned to the reference (2026-06-11)

The first port used the simple `sp_mlx.generate_sp` loop, so answers were unstable (trapped in `<think>`,
empty, or looping). Ported the stabilizing decode policy from `tiered_rag_mlx`:
- **`SPModel.cleanQuote`** (port of `_clean_quote`) — recall/lookup generate from an isolated context,
  think briefly, then **force-close `</think>`** and generate the answer (never trapped in think); empty/
  degenerate answer → fall back to the last `\boxed{}`. Used with up to 3 grounded re-rolls.
- **Loop guard** — `rep ≥ 6` identical-token break in `continueStream` (and `rep ≥ 5` in `cleanQuote`),
  + `looksDegenerate` (3-gram ×4) in the groundedness gate.
- **Think forcing** — `<think>\n` (`thinkOpen`) appended after `…<｜Assistant｜>` in `ChatSession.reply`
  and `cleanQuote`, matching the reference.
- `extractAnswer` surfaces a `\boxed{}` trapped inside think for the bounded path.

On device, the lookup turn now returns a clean grounded answer — "The current Emperor of Japan is Emperor
Naruhito." — with the groundedness guard re-rolling once to reach it. (Still TODO: the 2-pass
"Final answer:" continuation for the *bounded* command/math/chitchat path, and the per-turn timeout.)
